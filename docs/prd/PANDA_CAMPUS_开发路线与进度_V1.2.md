# PANDA CAMPUS｜开发路线与进度 V1.2

**用途**：SFOS 产品负责人 × 开发队友的实施与交付追踪表。  
**日期**：2026-10-17  
**项目**：胖达校园（V0 试点 → 自主发布与合作）  
**原则**：先有真实数据和可调用信息，再开放主体自主发布与 Mini-Contract。  
**进度说明**：以下状态全部为「待核对」，**不代表已实施或未实施**；由项目成员查看代码/演示后手动标注。没有自动监测或虚构百分比。

## 01｜两阶段目标与边界

### 阶段一 · 当前开发：搜索、浏览、AI 百科式推荐

**用户可做：**在校园浏览、筛选、搜索就业/创业、商家、社团/主体名片和活动；通过胖达获得有数据依据的百科式问答与相关推荐。  
**数据由谁维护：**SFOS 先作为 FDE 数据代理收集、核验、上传与更新，不依赖商家/社团自行发布。  
**开发边界：**数据库、代理运营录入、Information Card、三级语义缩放、基础检索与只读 Mini-App、胖达只读查询；CTA 仅走真实存在的查看/联系/官方渠道。  
**阶段完成依据：**同一条核验卡片能在校园和胖达返回相同 `card_id`，并能访问其可靠详情与负责人。

### 阶段二 · 后续建设：主体自主发布、Mini-Contract 与合作

**用户可做：**获得授权的个人、商家、社团及组织自己创建和维护卡片，并可在真实功能支持时发起报名、申请、合作等行动。  
**发布流程：**给胖达文字/图片/文件 → AI 整理草稿 → 用户确认发布身份与公开范围 → 必要审核 → 发布并写入账本。  
**开发边界：**主体账户权限、草稿/审核/更新机制、Mini-Contract 的条件/授权/执行/反馈；不自动代表用户签约或公开发帖。  
**阶段完成依据：**真实主体不再依赖 SFOS 代理就能合法发布和更新；另一主体可以发起可接收、可追踪的合作或合约行为。

**明确不在阶段一建设**：自研支付托管、完整电子合同平台、独立短视频社区、主体全自动无审核发布、虚构图书馆预约、没有数据支撑的实时客流与评分、没有真实坐标的地图点位。

## 02｜第一阶段：最短可交付链路

```text
SFOS 采集四类资料并核实授权
            ↓
资料上传与结构化录入（运营侧）
            ↓
主体归属、有效期、审核、入库
            ↓
校园 Tab：分类浏览／搜索／筛选／语义缩放
            ↓
胖达：检索数据库 → 百科式问答／可解释推荐
            ↓
Information Card → 只读 Mini-App／真实联系或官方入口
```

### M0 — 资产就绪与任务建立

- [ ] 建立公司可控的 Git 仓库、测试环境及访问权限；小程序 AppID/部署权限交由适当人员管理。
- [ ] 将已确认 UI 母版、PRD V1.2、Card Schema、按钮视觉规范和本开发路线放到资料目录。
- [ ] 选出就业、商家、社团、活动各类真实可公开的初始样本；记录核验方、时间与可用联系方式。

**验收**：开发人员能从统一目录取到当前版本的规格，拥有可运行的项目环境及至少一条经核实的示范记录。  
**前置条件**：账号开通、真实数据授权。  
**负责人**：产品/SFOS 提供资料与权限；开发者建立仓库、项目与基础环境。

### M1 — 数据库、主体归属与运营录入

- [ ] 建立 `Entity / InformationCard / EntityRelation / MediaAsset / ChangeLog` 的最小可查询结构。
- [ ] 四类信息具备最小字段（详见校园 Tab PRD 4.3）；分开记录真实发布者/责任主体与 SFOS 代理上传者。
- [ ] 实现运营录入、审核、更新、下架、有效期；允许批量导入经核验的数据。
- [ ] 对外数据只返回**已发布、有效、允许访问**的内容；保留原始资料与版本。

**验收**：SFOS 人工录入四类样本，能通过查询接口读回；更改/下架后结果同步且记录修改人。  
**依赖**：M0 样本及账户权限。  
**负责人**：开发者实现；SFOS 代理维护和核实内容。

### M2 — 校园信息浏览与检索

- [ ] 按母版实现品牌/系统胶囊、头像/触达/消息、搜索/筛选/地点及纯文字底部三 Tab。
- [ ] 首页分类固定 **全部｜就业｜商家｜社团｜活动**；蓝/黄/紫/绿对应四类业务。
- [ ] 数据库驱动大图卡（默认）→ 双列橱窗 → 紧凑列表；三个状态共享 `card_id`。
- [ ] 搜索关键词、按类别/时间/地点/关键属性筛选，支持空态与失败重试。
- [ ] 展示只读二级 Mini-App 和真实责任主体链接；CTA 不伪造申请、报名、咨询已成功。
- [ ] 实现 `viewMode=feed/map` 的同层切换接口：分类与底部栏原位，上栏目默认白底、地图态渐变磨玻璃、底部白底无 blur；即使尚无地点数据，也不得改变已完成的信息流母版。

**验收**：同一条真实信息可按分类被找到并在三级密度稳定展示，点击进入同卡详情，返回后保留筛选与滚动锚点。  
**依赖**：M1 数据接口。  
**负责人**：开发者（UI 与前后端联调）。

### M2-P1（数据就绪后）— 地点地图联调，不阻塞阶段一主线

- [ ] 取得正式地图底图使用授权、试点校区及可信 `place_id` 经纬度，关联 `CardPlaceRelation`。
- [ ] 地图仅替换**分类栏下方—底部全局栏上方**的内容视口；上栏目玻璃背景和底部纯白原位，所有筛选/分类条件共用。
- [ ] 建立地图地标与就业/商家/社团/活动信息卡集合；抽屉 `peek/half/expanded` 仅占内容视口。
- [ ] 完成 MAP-01–MAP-14 地图验收；缺少真实地点时可以交付 UI 壳，但不得对外展示假位置。

**完成状态：待核对 / P1 条件项**。交付证据包括实地核验地点表、地图 SDK 授权、同卡 ID 路径录屏与真机截图。**不得把地图作为 M3 数据库问答的前置条件。**

### M3 — 胖达数据库调用与百科式推荐

- [ ] 为胖达提供经过权限过滤的只读检索工具，支持类别、关键词、时间、地点等条件。
- [ ] 问答和推荐引用数据库中的 `card_id`、真实字段、更新时间与主体，不得编造不存在的数据。
- [ ] 推荐依据可解释：匹配岗位类型、活动时间、地点与当前有效性；无结果必须明确说明。
- [ ] 卡片更新或下架后，胖达不再展示失效的有效机会；记录必要的错误日志与用户授权反馈。

**验收**：同一条信息先在校园出现，再能被胖达以自然语言查询召回；信息修改后两处同步；无匹配时不幻觉。  
**依赖**：M1 数据模型与 M2 卡片详情链接。  
**负责人**：开发者（接口）；产品/SFOS 核对回答事实与范围。

### M4 — 联调验收与试点交付

- [ ] 选择就业、商家、社团、活动各一条经核验记录，跑通「录入 → 浏览 → 胖达召回 → 详情/联系」路径。
- [ ] 验证审核、失效、空结果、无网络、跨三种密度、主体责任跳转及按钮图文布局。
- [ ] 交付仓库最新代码、运行说明、测试账号配置、接口文档、演示地址/视频与已知问题清单。
- [ ] 地图在地图底图授权/坐标/地点关联表齐备后按 M2-P1 联调；未完成时记录 P1 依赖而不阻塞第一阶段核心闭环。

**验收**：产品负责人依据 PRD 的验收案例确认；关键 P0 流程实际可运行，并且没有把模拟状态当成功回执。  
**依赖**：M0–M3。  
**负责人**：开发者提交；产品负责人验收；SFOS 数据运营核查内容。

## 03｜第二阶段：将发布权与合作权交给真实主体

### M5 — 主体账户认证、权限与可追溯身份

- [ ] 为人、组织、商家配置真实主体管理权限；所有人可以被查看，但并非每个人都能代替某组织发布。
- [ ] 保留 `entity_id`、`card_id`、`created_by`、`on_behalf_of`、发布审核与历史修改记录。

### M6 — Agent 辅助创建与自主发布

- [ ] 主体发来文字、图片、文件或语音，胖达生成对应 Information Card 草稿并提示缺失信息。
- [ ] 用户编辑、确认公开范围、确认发布身份；必要时经过校方/平台审核后入库发布。
- [ ] 主体可再次更新/下架自己的信息，保留版本与有效期，不发生 SFOS 代理数据迁移断裂。

### M7 — Mini-Contract 与合作流程

- [ ] 用户可在真实能力范围内发起报名、申请、咨询、加入、合作意向等具体行动。
- [ ] 每项能力有前置条件、输入、权限、执行者、回执与状态；双方确认前不能把意向当作生效合同。
- [ ] 行动状态及履约反馈关联到主体账本；需支付/法律合同的部分必须由合规服务与真实责任人处理。

**第二阶段验收**：一位获得授权的主体能独立发布并更新卡片，另一个主体能够从 CTA 发起真实可接收的行动并看到可核验的处理结果。实际业务权限和第三方接口未就绪时，不得宣称已形成履约闭环。

## 04｜首批内容分类与颜色（两阶段共用）

| 首页分类 | 大标签 | Token / 建议色 | 阶段一入口 | 阶段二新增能力 |
|---|---|---|---|---|
| 就业 | 就业／创业 | `opportunity` · `#3478F6` 蓝 | 岗位、实习、创业机会查询 | 自主发布招聘、投递/申请、合作 |
| 商家 | 商家 | `merchant` · `#F7BE22` 黄 | 店铺信息、服务查询及实际联系方式 | 主体上新、咨询、预约、履约 |
| 社团 | 社团／组织／个人 | `identity` · `#9258D8` 紫 | 组织/个人名片、负责人、公开活动 | 主体管理、加入申请与项目协作 |
| 活动 | 活动 | `event` · `#25A96B` 绿 | 查看主办方、活动安排及报名渠道 | 主体自发布、报名、签到与反馈 |

`全部` 是聚合，不是独立业务类别。分类颜色只用于大标签和地图标记，关键 CTA 仍统一品牌黄；分类标签 ≤2 字，与标题同一行紧贴标题左侧。

## 06｜交付物与职责

| SFOS / 产品与运营 | 开发队友 |
|---|---|
| PRD 与 UI 母版、四类业务原始材料、字段含义、公开授权与真实性核验、最终验收 | 仓库/数据库、录入接口、校园前端、卡片渲染、检索工具、Agent 接口联调、测试与文档 |
| 第一阶段负责代理上传和维护，向开发者说明哪些是真实功能 | 实现真实可用的详情/联系路径，声明尚未接入的动作，提交可运行成果 |
| 第二阶段确认主体权限、审批流程和合作规则 | 在现有本体结构上实现自主发布与 Mini-Contract，避免重建数据库 |

**地图同框补充规则**：地图采用 `viewMode=map`，不增加第四档语义缩放；不改变顶部四层及底部栏的几何与分类条件，地图态顶部磨玻璃而底部仍白底。详细设计见《地点地图 UI 与交互规范 V1.2》。

**唯一优先级**：让 SFOS 可以持续上传真实信息，让学生可以在校园找到信息，并让胖达用数据库向学生提供可靠答案。用户自主发布和合作，是这套基础能力的第二阶段，而不是第一阶段必须完成的功能。
