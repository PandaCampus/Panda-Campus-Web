# PANDA CAMPUS · 地点地图 UI 与交互规范

**版本：V1.2｜2026-10-17**  
**适用范围：校园 Tab 内的「地点」视图状态及其底部地点集合；不涉及新建全局 Tab。**  
**状态：实施方案 / 基于已有界面母版修订；尺寸为建议值，微信真机验证后确认。**

## 01｜一句话定义与不可变约束

**地图是校园信息流的空间浏览方式，不是独立小程序首页，也不是第四级语义缩放。** 点击「地点」时，只切换从**分类栏下缘**到**底部全局 Tab 上缘**之间的内容视口，顶部四层的控件位置与底部栏目完全不变。

| 区域 | 信息流默认 | 地图视图 | 是否允许布局变动 |
|---|---|---|---|
| 第 1 层：PANDA CAMPUS + 微信原生胶囊 | 以白色为基底 | 渐变磨玻璃，图文位置不变 | **否** |
| 第 2 层：头像/名称 + 触达/消息 | 白底，两个横向长方形按钮 | 位置/形状不变，背景与顶部一起磨玻璃 | **否** |
| 第 3 层：搜索框 + 筛选/地点 | 白底，筛选/地点为近方形、图标上文字下 | 原位；地点显示选中态；背景磨玻璃 | **否** |
| 第 4 层：全部/就业/商家/社团/活动 | 一行固定的分类导航 | 原位、原顺序、同一选中状态；渐变玻璃背景 | **否** |
| 第 5 层：内容视口 | 大图卡片/双列橱窗/紧凑列表 | 地图底图/地标/地图内抽屉 | **允许替换** |
| 底部固定栏：校园/胖达/我 | **不透明白色**，三个纯文字 Tab | **仍是不透明白色**，不磨玻璃、不添加图标 | **否** |

**版本优先规则**：V1.2 明确顶部默认是白色基底；地图态切换为渐变磨玻璃。此前将校园实景摄影作为默认顶部强制背景的描述不再作为必须项。若使用旧母版的极淡校园摄影，只允许在品牌层且需确保默认视觉仍然是白底，不能影响控件对比度。

## 02｜三种核心状态，而不是三张不同页面

| 状态标识 | 定义 | 用户看到的内容 | 进入/离开 |
|---|---|---|---|
| `feed` | 默认信息浏览 | 大图卡片；用户可缩放至橱窗或列表 | 首次进入校园；地图态点「地点」返回 |
| `map` | 同一个校园 Tab 的地图浏览状态 | 真实地图 + 真实点位；没有独立顶栏 | 点「地点」切入；顶部、底部维持固定 |
| `map.placeSheet` | 地图内地点卡片抽屉状态 | 选中的 `place_id` 对应多类卡片 | 点地标打开；下滑收起，仍停留在地图 |

另有条件性叠加层：`filterSheet`（沿用同一套筛选面板）、`search`（沿用搜索页或搜索输入状态）、`miniApp`（Card-to-Mini-App）和 `miniContract`（Button-to-Mini-Contract，按实际可用能力）。这些不是新的全局 Tab。

**状态数据结构（前端建议）**：`viewMode: feed | map`、`feedDensity: large | showcase | list`、`selectedCategory`、`searchQuery`、`filters`、`sort`、`campusId`、`mapCamera`、`selectedPlaceId`、`sheetState: closed | peek | half | expanded`、`feedScrollAnchor`。

- `feedDensity` 在切入地图时冻结保留，返回信息流后恢复；地图不参与三级密度缩放。
- 分类/搜索/筛选由两种视图共享；地图只投影满足条件且有**可核验空间关系**的对象，不能为了上图补假坐标。
- 二级 Mini-App 返回时，恢复来源视图、位置、分类和选中地标；不能出现两个不同版本的同一张 Information Card。

## 03｜地图视觉：上玻璃，下纯白，中间连贯

### 3.1 默认信息流（Feed）

- 顶部品牌与三层控件、分类栏都使用**不透明白色基底 `#FFFFFF`**；必要时只有极低对比的品牌层装饰，不干扰功能。
- 中间信息流遵循既有设计：白底、细灰边、类别小标签蓝/黄/紫/绿、CTA 统一品牌黄。
- 底部全局栏 `#FFFFFF` 不透明；固定 3 纯文字 Tab，无图标。

### 3.2 地图视图（Map）

- **顶部玻璃化是背景状态变化，而非重新布局。** 第 1–4 层的高度、控件顺序、控件尺寸、横纵图文结构、点击热区全部不变。
- 顶部背景使用**纵向渐变半透明白色 + 适度 backdrop blur**；视觉建议 `rgba(255,255,255,.92)`（顶端）渐变至 `.66`（分类栏下缘），`blur(14px)` 起步，允许 12–18px 真机调校，底缘可用轻淡过渡羽化（24–40px）。
- 为实现 Airbnb 式地图连贯感，可让地图的**非交互视觉底图**在顶部玻璃背景下方延伸取样；但地图的**手势触控区仍严格限制在中间内容视口**，不得透传到搜索、分类、触达或微信胶囊。
- 顶部搜索、按钮、分类文本必须保持深色高对比：磨玻璃层可根据背景自动增加白色遮罩，保证文字和线性图标可读。低端设备/无背景模糊能力时回退至半透明高遮罩或不透明白色，结构完全不变。
- 地图内容区域占用**分类栏下缘至底部固定 Tab 上缘**的全部可用高度；地图不把底部栏变成漂浮悬浮按钮，也不挤压底部安全区。
- **底部保持纯白 `#FFFFFF`，不应用透明、磨玻璃或地图穿透效果**；顶部可有渐变，底部必须明确分离。
- 「地点」按钮仍是第 3 层的**近正方形（图标在上、文字在下）**；激活态只用微弱描边/文字变化表示，不增加全局导航按钮或把文字改为“视图”。

### 3.3 视觉 Token（建议实施，不是已量产测量）

| Token | 建议值 | 说明 |
|---|---|---|
| `map.header.base` | `#FFFFFF` | 默认 Feed 顶部不透明白底 |
| `map.header.glass.top` | `rgba(255,255,255,.92)` | 地图态顶部开始处 |
| `map.header.glass.bottom` | `rgba(255,255,255,.66)` | 地图态分类栏下缘处 |
| `map.header.blur` | `14px`（允许 12–18px） | 微信真机及设备性能测试 |
| `map.header.feather` | `24–40px` | 仅渐变羽化，不占用新的布局高度 |
| `map.footer.base` | `#FFFFFF` | 始终不透明、无 blur |
| `map.pin.job` | `#3478F6` | 就业/创业；标记加形状/文字，不只用色 |
| `map.pin.merchant` | `#F7BE22` | 商家 |
| `map.pin.identity` | `#9258D8` | 社团、组织、个人名片 |
| `map.pin.event` | `#25A96B` | 活动 |
| `map.pin.mixed` | 中性深灰 | 多类卡片共址或聚合 |

## 04｜顶部各控件在两种浏览状态下的行为

1. **PANDA CAMPUS / 微信胶囊**：位置不变，微信原生胶囊仍由平台控制；地图绝不覆盖系统胶囊。
2. **头像 → 个人主体主页**：地图态与信息流态一致，返回时保留地图相机与地点选择。
3. **触达 / 消息**：右侧仍是横向长方形、左 NFC 四角扫描框+右「触达」、左信封+右「消息」；不得变成地图控制。
4. **搜索**：同一搜索入口；关键词条件复用到卡片列表和地图标记。结果无真实坐标的卡片在信息流依然可检索，地图应明确说明“部分内容暂未关联地点”，不伪造点位。
5. **筛选**：同一筛选抽屉，维度→筛选项→组合结果；启用某项后，顶部分类和地图点位/地点集合同时更新。筛选抽屉关闭后仍留在当前视图，不强迫回到卡片流。
6. **地点**：作为 `feed ⇄ map` 切换器，图标/文字/位置不变。首次进入地图以**试点校区的已核实地理范围**为初始视口；再次点击「地点」回到进入前的大卡/橱窗/列表状态。
7. **分类栏**：保持 `全部｜就业｜商家｜社团｜活动` 同一排，筛选条件双向同步；地点抽屉不再复制第二套大分类 Tab，避免上下重复。

## 05｜地图地点、混合类别与底部卡片集合

### 5.1 地标不是单张卡片

- **地标 = 地点主体 `place_id`**。同一个地点可关联多张不同类别 Information Card，例如图书馆附近的活动、商家、岗位、社团。
- 点击**单一类别地标**，可先显示地标小标签，底部 `placeSheet` 打开该地点的**混合类别卡片集合**；顶部分类当前若非「全部」，则展示筛选后的集合。
- 多类别共址：在一个地点上显示**中性数字聚合标记**或混合地标，而不是四个彩色图标叠在完全相同坐标；点开后由卡片标签呈现蓝/黄/紫/绿。
- 地点数量和关联卡片数分别统计；不能把“1 个地点有 8 张卡片”误标为“8 个地点”。
- 点击密集聚合标记先放大或展开聚合；点击具体地点才打开抽屉。

### 5.2 地点集合的 3 档抽屉（**限地图视口内部**）

| 档位 | 建议可见面积（相对地图内容视口） | 内容 | 触发方式 |
|---|---|---|---|
| `peek` | 26–32% | 地点名称、关联卡数、1 张精选信息卡/紧凑横滑卡 | 初次选中地标 |
| `half` | 50–60% | 地点信息、3–5 张符合筛选的卡片 | 上滑一次 |
| `expanded` | 78–86% | 该地点全部有权限且有效的信息卡列表，内部独立滚动 | 继续上滑 |

**重要：百分比以“地图内容视口”为计算基础，不是整个手机屏幕。** 抽屉绝不可遮住上方分类栏或下方三个纯文字 Tab。无图标自定义底部导航。收起抽屉不改变地图中心与筛选条件。

每张集合卡仍沿用统一卡片规则：媒体 → ≤2 汉字分类标签（与标题同一行）→ 时间 → 地点 → 关键属性/数据 → 独立 CTA；集合可使用紧凑卡，但不等于将整个校园视图切到列表档位。

### 5.3 关键交互路径

```text
校园信息流（保留当前密度 large/showcase/list）
    ├─ 点「地点」→ 地图视图（同层替换内容区域）
    │       ├─ 顶部分类/搜索/筛选（同一状态）→ 地图点位实时更新
    │       ├─ 点聚合标记 → 局部放大或拆分
    │       └─ 点 place_id → 底部卡片集合 Sheet
    │                ├─ 点卡片主体 → Card-to-Mini-App
    │                ├─ 点 CTA → Button-to-Mini-Contract（仅真实已启用）
    │                └─ 点地点/主体链接 → 对应地点或主体主页
    └─ 地图点「地点」或系统返回 → 恢复之前的 feedDensity、筛选、滚动锚点
```

从 Mini-App 的地点信息进入地图时，带 `place_id` 与来源上下文；返回 Mini-App 而非无条件返回首页，且地标与卡片继续引用同一 `card_id`。

## 06｜地图数据要求：最小可信版

| 模型 | 最小字段 | 规则 |
|---|---|---|
| `Place` | `place_id`、`campus_id`、公开名称、坐标、`verified_at`、`visibility` | 坐标需经过核验；不能凭模型编造 |
| `CardPlaceRelation` | `card_id`、`place_id`、`relation_type`、`verified_at` | 关系类型示例：`held_at` 举办地、`located_at` 常驻、`service_area` 服务范围、`nearby` 邻近；不混淆 |
| `InformationCard` | `card_id`、`type`、`publish_status`、有效期、主体、可用 CTA | 与信息流和胖达使用同一主记录 |
| `mapCamera` | `campus_id`、地图中心、缩放级别、可选边界框 | 保留用户当前浏览区；不上传精确位置作默认条件 |

- 地图首屏仅加载**已公开、已核验、坐标正确、仍有效且用户有权查看**的卡片与地点关系；禁止把纯线上工作岗位放到校内虚构地标。
- 位置信息未知：该记录不在地图上设点；仍可通过搜索、信息流和胖达检索。地图无结果时有清晰空态与「返回信息流」，不展示冒充真实的地图样例。
- 未授权精准定位：用户仍可手动选校区或查看已确认校园范围；仅在用户明确授权且确有需求时使用定位，不能用估计位置冒充精确坐标。
- 当前地图没有室内层级数据时，不显示 1F/2F/3F 控件；没有授权底图时不能使用第三方地图贴图。
- 建议 API：`listPlaces({campusId,bounds,category,filters,query})`、`listCardsByPlace({placeId,filters,query})`、`getPlace(placeId)`；服务端进行权限、审核和有效期过滤。

## 07｜手势、层级、无障碍和性能

- 地图拖动、双指缩放仅在地图内容视口生效；顶部搜索、分类、消息与底部 Tab 的触控事件优先，不接受地图透传。
- 地图移动后可出现内容视口内「搜索此区域」控件，避免每次轻微拖动都重新请求；它不改变全局顶部工具栏。
- 卡片抽屉内部滚动与地图缩放区分：抽屉内手势优先滚动卡片，抽屉顶部拖拽柄调节 `sheetState`，不得同时拖拽地图。
- 显示白底加载骨架、网络失败与重试；地图 SDK 不支持 `backdrop-filter` 时，白色高遮罩降级，不为了玻璃效果牺牲可读性或帧率。
- 所有图标需提供名称/可访问语义；对比度达基本可读要求；不可仅以蓝黄紫绿编码业务类别，地标也应有可分辨图形或文案。
- 390 CSS px 为初始设计基准，375/390/430 px 真机测试；实际内容区域高度动态计算，尤其避开胶囊、安全区及底部全局 Tab。

## 08｜场景级验收用例（地图专属）

| ID | 操作 | 通过标准 |
|---|---|---|
| MAP-01 | 从大图卡点「地点」 | 仅信息流视口换成地图；品牌/头像/搜索/筛选/分类/底部栏几何不变 |
| MAP-02 | 观察背景切换 | 默认上栏目白底，地图态上栏目渐变磨玻璃；底部**始终纯白无模糊** |
| MAP-03 | 比较工具按钮 | 「触达/消息」横排长方形，「筛选/地点」近方形纵排；四个图标和文字完整 |
| MAP-04 | 切换顶部「就业」标签 | 地图只显示符合当前类别与筛选的真实地标；返回信息流类别一致 |
| MAP-05 | 地图态打开并应用筛选 | 打开同一个筛选面板；关闭后继续显示地图；点位与卡片结果一致 |
| MAP-06 | 点包含多种类别的图书馆地标 | 地图底部出现同一地点多类卡片集合，不只出现单张地点介绍卡 |
| MAP-07 | 上下拖动地点抽屉 | `peek/half/expanded` 只占中间地图视口，不覆盖品牌/分类或底部 Tab |
| MAP-08 | 点聚合标记/同点多类别 | 聚合数量正确、不会出现相互覆盖的四枚同点图标；可进入具体地点 |
| MAP-09 | 集合卡片主体/CTA 点击 | 卡片进入 Mini-App；CTA 仅在真实已接入时进入 Mini-Contract 或真实入口 |
| MAP-10 | 从二级详情点击地点并返回 | 跳到对应 `place_id`，返回原二级详情且筛选/地图相机仍在 |
| MAP-11 | 再次点击「地点」返回信息流 | 恢复原来的大图/橱窗/列表、滚动位置和筛选状态 |
| MAP-12 | 无经纬度/无权限/无网络 | 不编造地标、距离、人数；有空态/降级/重试；地图不阻断信息流 |
| MAP-13 | 缩放、拖动地图并点击顶部控件 | 地图手势不影响顶部或底部控件的命中区域 |
| MAP-14 | 在 375/390/430 px 真机测玻璃层 | 文字清楚，背景模糊降级有效，原生微信胶囊与底部安全区不重叠 |

## 09｜版本边界与交付物

**第一阶段 P0**：完整校园信息流、三级密度、搜索/筛选、胖达对数据库的百科式查询与真实卡片召回。地图的 UI/状态容器可先实现，但**带真实地点标记的正式上线属于 P1 数据就绪条件项**。

**条件式地图上线前必须准备**：底图使用授权、校区范围/坐标、地点主体 `place_id`、卡片与地点的关联表、至少可复测的跨类别地点集合。没有这些，不允许用演示地标替代已上线地理数据。

**交付开发者**：页面状态机、顶部玻璃态 Token、地点抽屉 3 档、类别同步规则、真实地点 API 约束、`MAP-01…MAP-14` 验收，以及基于此前母版的视觉草图。地图图面风格可参考 Airbnb 式底图与卡片抽屉，但**不得复制其独立顶部导航或底部图标**。
