# PANDA CAMPUS · 校园 Tab PRD 核心摘要

**定位：校园本地信息发现与行动入口**  
**版本：V1.2（地图同框与顶部玻璃态修订）｜2026-10-17**  
**范围：仅校园 Tab 及其进入的搜索、筛选、地点、主体主页、业务 Mini-App 与行动入口。**

校园 Tab 连接真实的就业、商家、社团与活动信息。信息来自统一数据库，通过 Information Card 展示，通过主体关系与实际服务建立联系。

## 1. 全局页面结构

固定阅读顺序：**品牌栏 → 主体与沟通栏 → 搜索工具栏 → 分类导航 → 信息流 → 底部导航**。

- 品牌栏：`PANDA`（黑色）`CAMPUS`（黄色），右侧微信原生胶囊；**默认白底、地图态只变顶部磨玻璃背景**。
- 主体栏：左侧头像与名称；右侧仅「触达」「消息」两个**横向长方形**按钮，**图标在左、文字在右**。触达使用 **NFC 四角扫描框**；消息使用**信封线框**，有未读时右上角显示黄色小点。
- 工具栏：左侧搜索框；右侧「筛选」「地点」为两个**近正方形**按钮，均采用**图标在上、文字在下**的结构；筛选使用**漏斗**图标，地点使用**定位图钉**图标。
- 两组按钮不可互换形态或跨层合并；视觉建议为触达/消息 **70–78×40–44 px**、筛选/地点 **50–54×50–54 px**，所有按钮点击热区不少于 44×44 px。
- 底部：**校园｜胖达｜我**，三个纯文字 Tab，仅当前项使用黄色短下划线。

## 2. 内容分类

| 类别 | 颜色 | 内容 |
|---|---|---|
| 就业、创业 | 蓝 | 实习、兼职、招聘与创业机会 |
| 商家 | 黄 | 商品、商家、校园生活服务 |
| 社团、组织及个人名片 | 紫 | 主体身份、关系、组织与能力 |
| 活动 | 绿 | 讲座、比赛、交流、校园活动 |

首页快捷分类：**全部｜就业｜商家｜社团｜活动**。个人名片等通过搜索、主体关系进入，不额外增加一级分类。

**四类数据在第一阶段由 SFOS 代理采集、核验、上传**，采集要求如下：就业至少确认发布企业/组织、岗位/机会、条件、期限及真实申请/联系渠道；商家确认经营主体、服务内容、地点/服务范围、时间及真实联系方式；社团确认组织身份、负责人及公开活动/招新状态；活动确认主办方、负责人、时间、地点、参与条件及官方报名方式。所有资料需保留版本、代理上传人与责任主体关系。

## 3. Information Card 与三级语义缩放

统一信息层级：**媒体 → 大标签＋标题 → 时间 → 地点 → 关键小标签 → 关键数据 → 关键 CTA**。

- 大标签**最多两个汉字**，与标题同一行，紧贴标题左侧。
- 三级语义缩放：**大图卡片（默认）→ 双列橱窗 → 紧凑列表**。共享同一信息与 Card ID。
- 真实浏览量**严格超过 1,000** 才显示；更有决策价值的业务数据可以优先展示。
- 关键 CTA 独立于信息与社交互动，保持在业务信息区右下角；不展示未接入的假功能。
- 如启用点赞，点赞兼具喜欢与收藏性质；不在媒体右上角设置独立收藏按钮。

## 4. 搜索与筛选

筛选结构：**维度 → 筛选项 → 组合结果**。

首页只承担基础搜索和结构化筛选；支持类别、时间、地点、条件属性、排序。就业、商家、社团、活动按实际字段展示不同的专属筛选项。查询需遵守审核状态、有效期及访问权限。

## 5. 地点地图（V1.2 重点）

**地点是同一个校园 Tab 内的空间视图，而非第四档缩放，也不新建上下导航。**

- **唯一变动区域**：分类栏下缘至底部「校园｜胖达｜我」上缘；地图仅替换其中的信息流内容。
- **顶部原位**：PANDA CAMPUS/微信胶囊、头像/触达/消息、搜索/筛选/地点、全部/就业/商家/社团/活动，几何位置和点击热区全部不动。
- **玻璃规则**：默认上栏目为不透明白底；进入地图后仅顶部四层背景切换渐变磨玻璃（建议白色透明度 .92→.66、模糊 14px）；**底部栏保持不透明纯白，绝不磨玻璃**。
- **数据与筛选**：地点标记遵循已有蓝/黄/紫/绿四分类；顶部标签、搜索与筛选在两种视图间同步，地图不另加重复分类栏。
- **地标 → 卡片集合**：点击同一 `place_id` 打开地图内容视口内的底部可拖拽抽屉，聚合该地点的就业/商家/社团/活动真实卡片。点击卡片进 Mini-App；点击有效 CTA 进 Mini-Contract。
- **返回与真实性**：地图与信息流来回切换，保留原大卡/橱窗/列表状态、筛选与滚动锚点；无真实坐标、底图授权或室内层级数据时不得虚构点位、距离或楼层。

地图视图的详细状态、抽屉、数据接口、尺寸 Token 与验收见独立 `03_地点地图专题/`。第一阶段地图仍按真实数据条件作为 P1 联调，不阻塞 P0 浏览搜索与胖达数据库推荐。

## 6. 主体主页

长期主体包括个人、组织、商家。通用局部导航：**主页｜动态｜照片**。

- 主页：身份、能力、关系及可配置组件。
- 动态：获授权公开的信息卡发布与更新记录。
- 照片：获授权展示并关联信息卡的媒体资产。

商家关联经营者，社团关联负责人，活动关联主办方，就业信息关联发布企业或责任方。不同主体可有不同功能模板，但保留统一关系与身份机制。

## 7. 二级页面与行动

- **Card-to-Mini-App**：点击卡片主体进入对应主体或事项的完整微应用。
- **Button-to-Mini-Contract**：点击关键 CTA 进入真实可用的行动协议或服务流程。

就业、商家、社团、活动采用适配内容与能力的二级模板，不强制套用同一表单。

## 8. 两阶段开发路线

**第一阶段 · 当前必做：搜索、浏览、AI 百科式推荐**

SFOS 以数据代理身份，持续采集、确认和维护四类信息；开发数据库与运营录入、校园卡片流、三级语义缩放、基础搜索筛选，以及**胖达调用同一数据库进行百科式问答、检索与可解释推荐**。只展示真实可用的查看、联系或官方入口，不模拟尚未接入的提交/预约结果。

**第一阶段验收**：SFOS 上传已核验信息 → 数据库收录 → 校园可搜索浏览 → 胖达返回同一 `card_id` 的事实卡片 → 用户能进入只读详情或实际联系渠道。地图等依赖真实坐标的部分按数据条件联调。

**第二阶段 · 后续建设：自主发布和 Mini-Contract 合作**

授权主体通过胖达用文字、图片或文件提出发布需求 → Agent 生成结构化信息卡草稿 → 主体确认（及必要审核）→ 自主发布、更新与维护。再基于真实服务能力逐步支持主体自己发起合作、报名、申请及 Mini-Contract，记录条件、责任、执行和履约结果。**第二阶段不作为第一阶段上线前提。**

> 详细分类必需字段及本阶段/下一阶段的功能边界见 `02_完整正文/`；开发任务、依赖、可手动勾选的进度表见 `04_开发路线与进度/`。
