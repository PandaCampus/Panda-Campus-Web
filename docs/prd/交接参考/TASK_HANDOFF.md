# SFOS 任务逻辑与创建表单交接

本文件对应当前运行中的 `https://pandacampus.cn/sfos/workspace`。任务由已登录成员在工作台的“创建任务”表单创建，时间统一按北京时间（UTC+08:00）解释。初始 7 项仅为标明“示例”的演示任务。

## 创建任务表单

| 字段 | 表单类型 | 必填 | 规则 | 接口字段 |
| --- | --- | --- | --- | --- |
| 任务名称 | 单行文本 | 是 | 去首尾空格后 2–100 字 | `title` |
| 任务说明 | 多行文本 | 否 | 去首尾空格后最多 500 字 | `description` |
| 计划完成时间 | 日期和时间 | 是 | 北京时间，必须晚于当前时间，最多提前规划 366 天 | `planned_at` |
| 优先级 | 单选 | 是 | 高 `3`、中 `2`、低 `1`；默认中 | `priority` |

表单不填写发布时间和实际完成时间。服务端在创建时写入 `published_at`；成员完成任务时才写入 `completed_at`。当前版本的任务默认属于已登录成员，接口不接受任意指定他人账号。

## 可直接提交的 JSON

请求：`POST /sfos/api/tasks/create`，`Content-Type: application/json`。请求必须带已登录会话 Cookie 和从 `GET /sfos/api/me` 返回的 `csrf` 值，放在 `X-SFOS-CSRF` 请求头。

```json
{
  "title": "完成校园 Tab PRD 评审",
  "description": "核对需求、页面流程和验收标准",
  "planned_at": 1792490400,
  "priority": 3
}
```

示例中的 `planned_at` 是 **2026-10-20 18:00 北京时间**对应的 Unix 秒数。下游若用 `datetime-local` 表单，应把用户输入的北京时间转换为 Unix 秒数再提交。成功返回 HTTP `201` 与 `{ "ok": true }`。可用的机器校验文件是 [task-create.schema.json](task-create.schema.json)，示例请求体是 [task-create.example.json](task-create.example.json)。

## 查询与状态字段

`GET /sfos/api/state` 返回 `tasks` 数组。每条是某一天的一次任务记录，主要字段如下：

| 字段 | 含义 |
| --- | --- |
| `id` | 本次任务记录 ID；勾选完成时提交此 ID |
| `template_id` | 原始任务 ID；资料和代码交付使用此 ID 关联 |
| `title`、`description`、`ordinal` | 名称、说明、项目内序号 |
| `published_at` | 本次记录创建/发布时间，Unix 秒 |
| `planned_at` | 本次记录计划完成时间，Unix 秒 |
| `completed_at` | 实际完成时间，未完成为 `null` |
| `missed_at` | 被判定为延后时的时间，未延后为 `null` |
| `priority` | `3` 高、`2` 中、`1` 低 |
| `copied_from` | 前一日记录 ID；原任务为 `null` |
| `sample` | `1` 为示例数据，`0` 为真实创建任务 |

## 每日进度与逾期复制

1. 以北京时间自然日对 `planned_at` 分组；每个有任务的日期单独显示 `已完成数 / 当日记录总数` 和进度条。
2. 日期从早到晚显示；同一日期内先按优先级从高到低，再按计划完成时间从早到晚排列。
3. 某日结束仍未完成的记录留在该日，显示“未完成 · 已延后”，并在该日期计一条“记过”。它的勾选状态不可再修改。
4. 服务端在次日首次读取任务时生成一份关联副本：保留名称、说明和优先级；计划完成时间移到次日同一时刻；副本的 `copied_from` 指向前一日记录。
5. 连续多日未完成时，每天留下一条延后历史，并为下一天再复制一条。重复读取不会产生重复副本。
6. 只能勾选当前未延后的记录。勾选时服务端记录实际完成时间；完成副本不会回改之前日期的“未完成 · 已延后”或其进度条。

勾选接口：`POST /sfos/api/tasks`，请求体为 `{ "task_id": 123, "done": true }`；取消勾选将 `done` 设为 `false`。请求同样需要会话 Cookie 和 `X-SFOS-CSRF`。

## 与项目资料的关系

资料上传到 `PANDACAMPUS` 文件夹。上传资料、提交代码时若关联任务，使用 `template_id`，因为同一任务可能在不同日期留下多条记录。当前项目资料包括 `PANDA_CAMPUS_校园Tab_PRD_V1.0_交付包.zip` 与 `胖达校园校园主页UI.zip`。

## 下游实现注意

- 保留每一天的历史记录，不要把逾期任务直接移动到次日。
- 不要根据文件上传或代码提交自动勾选完成；完成状态由成员手动确认。
- 实际完成时间由服务器生成，不接受客户端伪造。
- 文案中的“创建任务”对应上述创建接口；数据库中的 `published_at` 仍表示创建时间。
